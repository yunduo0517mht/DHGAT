## 一、图的构建

### 节点与边

- **节点**：LIAR 数据集中的每一条新闻（约 12,800 个）
- **边**：两条新闻在某个元数据特征上值相同，就连一条边
- 所有子图共享同一批节点，区别只在于边不同

### 6 种可选的特征图

| 特征 | 含义 | 连边规则 |
|------|------|---------|
| speaker | 发言人 | 同一个人说的两条新闻连边 |
| party_affiliation | 政党归属 | 同一政党的新闻连边 |
| subject | 新闻主题 | 主题相同的新闻连边 |
| state_info | 所在州 | 同一个州的新闻连边 |
| job_title | 职位 | 职位相同的新闻连边 |
| context | 发言场景 | 场景相同的新闻连边 |

此外还会自动生成一张**自环图**（每个节点只连自己），作为"不看邻居、只看自己"的选项。

### 节点特征（305 维）

每个节点携带的特征由两部分组成：

**5 个历史可信度统计值**（该发言人被 PolitiFact 核查的历史记录）：

| 字段 | 含义 |
|------|------|
| barely_true_counts | 历史上被判"基本不实"的次数 |
| false_counts | 被判"虚假"的次数 |
| half_true_counts | 被判"半真半假"的次数 |
| mostly_true_counts | 被判"大部分属实"的次数 |
| pants_on_fire_counts | 被判"彻底造假"的次数 |

**300 维文本嵌入**：使用 FastText 对新闻文本生成的句子向量。

> 5 个统计值 = 人物信用画像，300 维嵌入 = 文本语义信息，合计 305 维。

## 二、混合损失函数

DHGAT 使用两个损失的加权组合：

- **CrossEntropyLoss**：标准分类损失，衡量预测概率分布与真实标签的差距
- **自定义 L1 损失（MAE）**：把预测类别编号和真实类别编号当作数值，计算绝对差

**为什么需要 L1 损失？** 因为 6 个标签存在程度顺序（从"彻底造假"到"真实"）。CrossEntropy 不区分预测偏离的远近，但 L1 损失能惩罚"偏得越远，损失越大"。例如真实标签是 5（true），预测成 4 比预测成 0 损失更小。

**最终损失公式**：

> Loss = l1 × CrossEntropy + l2 × L1

上次跑测使用的参数：l1=0.7, l2=0.1

## 三、模型整体架构

1. **DHGAT_Layer_1**：305 → 256，决策网络选择在哪张子图上传播
2. **DHGAT_Layer_2**：256 → 128，再做一次决策+传播
3. **FC1**：128 → 64，普通全连接层
4. **FC2**：64 → 6，输出 6 个类别的概率

> 核心在前两层 DHGAT_Layer（选图+传播），后两层全连接只做分类。

## 四、整体 Pipeline

1. **加载数据**：从 HuggingFace 下载 LIAR 数据集，合并 train/val/test，打乱后存为 CSV
2. **下载 FastText**：获取预训练英文 300 维词向量模型
3. **提取文本嵌入**：用 FastText 对每条新闻生成 300 维句子向量
4. **划分数据**：按比例随机采样，为每轮迭代生成不同的训练索引
5. **构建图**：根据选定特征构建同构子图，存为 GraphML 文件
6. **训练模型**：加载特征 + 图 → 创建 DHGAT → 多轮迭代训练评估 → 保存结果

> 前 5 步是数据准备（只需跑一次），第 6 步是真正的模型训练。

## 五、决策机制（Decision Mechanism）

图是提前为所有新闻建好的，固定不变。决策机制选的不是"最终答案"，而是**"信息来源"**。

对每个节点做三步：

1. **打分**：用 decision 网络（GATv2）在固定图上传播，输出每张子图的分数
2. **决策**：通过 Gumbel-Softmax（hard=True）将分数变为 one-hot，选中一张图
3. **聚合**：在每张图上分别做 GAT 传播，用 one-hot 加权，实际只取被选中图的结果

> 例：新闻 A 在 speaker 图上连着 B、C，在 context 图上连着 D、E。决策机制决定 A 应该参考 B、C 还是 D、E 来更新自己的特征，更新后的特征再送入全连接层做分类。

## 六、Gumbel-Softmax 为什么能让离散选择可训练

### 6.1 什么是离散选择

DHGAT 有多张候选图，每层需要"选一张图"来用。选择结果是 one-hot 向量（只有一个 1，其余都是 0）：

```
[1, 0, 0]  ← 选第 1 张图
[0, 1, 0]  ← 选第 2 张图
[0, 0, 1]  ← 选第 3 张图
```

这就是离散选择——结果非 0 即 1，没有中间值。

### 6.2 为什么离散选择没法求导

神经网络学习靠的是：**算损失 → 对参数求导 → 沿导数方向调参数 → 损失变小**。求导要求操作是连续平滑的：输入变一点，输出也跟着变一点。

但 argmax（取最大值位置）是跳变的：

```
打分: [0.3, 0.8, 0.1]  →  argmax  →  [0, 1, 0]
```

- 把 0.8 微调成 0.81 → 结果还是 `[0, 1, 0]`，没变化，导数 = 0
- 把 0.8 调成 0.2 → 结果突变成 `[1, 0, 0]`，跳变，导数不存在

要么不变，要么突变。导数算不出来 → 梯度断了 → 决策网络没法学习。

### 6.3 普通 Softmax 能解决吗

Softmax 能把打分变成连续的概率：`[0.3, 0.8, 0.1]` → `[0.24, 0.45, 0.31]`，可导，梯度没问题。

但这不是"选一张图"，而是"三张图都用，只是权重不同"（软混合）。论文要的是硬选择：只用一张图，其他图贡献为 0。

所以：普通 Softmax **能求导但做不到硬选择**，argmax **能硬选择但求不了导**。

### 6.4 Gumbel-Softmax 的核心思想

它的解法很巧妙——在前向和反向传播时走不同的路：

- **前向传播**（算输出）：用 one-hot 硬选择
- **反向传播**（算梯度）：偷偷换成 softmax 的连续值来求导

这叫 **Straight-Through Estimator（直通估计器）**。对应代码 `dhgat_layer.py:29`：

```python
decisions = F.gumbel_softmax(decision_logits, tau=0.5, hard=True)
```

`hard=True` 就是开启这个模式。

### 6.5 这行代码内部做了三件事

**第一步：决策网络打分**

```python
decision_logits = self.decision(x, edge_index_dict[self.decision_key])
```

决策网络（GATv2）给每张候选图打分，比如某节点输出 `[1.2, 3.5, 0.8]`。

**第二步：加 Gumbel 噪声**

从 Gumbel 分布采样随机噪声，加到分数上：

```
原始分数:  [1.2,  3.5,  0.8]
噪声:     [+0.5, -0.3, +1.1]
加噪后:   [1.7,  3.2,  1.9]
```

为什么加噪声？训练初期决策网络还不靠谱，如果不加噪声，模型可能碰巧一直选某张图，永远不试别的。噪声引入随机探索，让模型"偶尔选一下别的图试试"。随着训练进行，打分差距拉大，噪声就翻不了盘了，选择自然稳定。

**第三步：除以温度 tau，做 Softmax，然后 hard 化**

```
soft = softmax([1.7, 3.2, 1.9] / 0.5)  →  [0.04, 0.91, 0.05]   # 接近 one-hot
hard = [0, 1, 0]                                                    # 真正的 one-hot
```

tau = 0.5（温度）控制输出多"尖锐"：tau 越小越接近 one-hot，越大越接近均匀分布。

然后 `hard=True` 的效果：
- 前向：输出 `[0, 1, 0]`（硬选择）
- 反向：用 `[0.04, 0.91, 0.05]`（连续值）算梯度

### 6.6 反向传播的软值 [0.04, 0.91, 0.05] 有什么意义

反向传播改的不是"这次选哪张图"，而是**决策网络的参数**。

举例：某轮训练硬选择了第 2 张图，结果损失很大（效果不好）。反向传播通过 `[0.04, 0.91, 0.05]` 这个连续值，告诉决策网络："你给第 2 张图打了 0.91 的信心，但结果很差，降低对它的信心。"

于是决策网络参数被调整，下一轮打分可能变成 `[2.8, 1.5, 0.9]`，硬选择就变成 `[1, 0, 0]`——改选第 1 张图了。

如果只有 `[0, 1, 0]`，梯度只知道"选了第 2 张"，不知道信心程度，调参就没有方向感。连续值提供了"方向和力度"，让决策网络能有效学习。

> 总结：每一轮训练都是硬选择，但通过反向传播不断调整决策网络的参数，让下一轮的硬选择越来越明智。这就是决策网络名字的由来——它学会了"做决策"。

## 七、异构图 vs 同构图：为什么多张图比一张图好

- **同构图**：把所有关系的边混到一张图里，模型不知道两个节点为什么相连
- **异构图**：每种关系单独一张图，模型能分别从不同角度获取信息，再通过决策机制选最有用的那张

> 同构图是一锅粥，异构图是分门别类、各取所需。分开才能让决策机制发挥作用。

## 补充：图构建的 feature_matrix 原理

`graph_construction.py` 对每种特征构建 N×N 的比较矩阵：

1. 把特征值映射为整数编号，如 `['张三','李四','张三','王五']` → `[0,1,0,2]`
2. 广播比较：把编号数组摆成一竖一横，逐个比较是否相等
3. 相等为 1（连边），不等为 0（不连边）

```
feature_matrix[i][j] = 1  →  节点 i 和 j 在该特征上值相同，连一条边
```

对角线永远为 1（自己等于自己）。每种特征生成一张不同的图。

## 补充：Transductive Learning（直推式学习）

GNN 训练时，**所有节点**（包括测试集）都参与图上的消息传播，但只有训练集节点的标签参与 loss 计算。测试集节点在图中提供结构信息，但标签从未被模型看到，**不存在信息泄漏**。

打乱数据的目的：让训练集和测试集节点在图上**交错分布**，避免各自扎堆。如果不打乱，训练集节点集中在一区、测试集集中在另一区，GNN 消息传播时两边缺乏交互，预测效果会下降。

> 这是 GNN 的标准做法，区别于传统机器学习的 train/test 完全隔离。

## 补充：DHGAT_Layer 中的两种 GATv2

一层 DHGAT_Layer 里有两个 GATv2Conv，职责不同：

- **self.decision**：在决策图上传播，为每张候选图打分 → 经 Gumbel-Softmax 变成 one-hot 选择
- **self.gat**：在每张候选图上做消息传播，聚合邻居信息更新节点特征

循环中 `self.gat` 在**每张图上都跑一遍**，但乘以 one-hot 权重后，只有被选中的图的结果被保留（其他图 × 0 = 丢弃）。

**所有图共享同一套 GAT 参数**（只创建了一个 `self.gat`），因为"区分不同图"的职责已经交给了 decision 网络，GAT 只需做通用的消息传播。共享参数的好处是参数量少、不容易过拟合。

## 补充：train() 函数的 5 个关键步骤

```
1. zero_grad()       → 清零上一轮的梯度（不然梯度会累加）
2. model(x, ...)     → 前向传播：把特征喂进模型，得到预测结果
3. loss_1 + loss_2   → 混合损失：CrossEntropy + L1，衡量预测有多差
4. loss.backward()   → 反向传播：算出每个参数对 loss 的梯度（方向）
5. optimizer.step()  → 更新参数：沿梯度方向微调参数，让 loss 变小
```

> 注意：第 4 步只是算出梯度，第 5 步才真正改参数。

## 补充：为什么保存验证集最高分的模型而非最后一个 epoch

训练过程中，训练集准确率一直上升，但验证集准确率**先升后降**——后期模型开始"死记硬背"训练数据（过拟合），对没见过的数据预测反而变差。最后一个 epoch 的模型很可能已经过拟合了。

保存验证集最高分的模型 = **在过拟合之前及时"存档"**，这是 Early Stopping（提前停止）的变体。

```python
if val_acc > best_acc:
    best_acc = val_acc
    best_model = copy.deepcopy(self.model)  # 存档当前最佳
```
